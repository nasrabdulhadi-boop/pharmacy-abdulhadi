# QA correction: account creation appeared unresponsive

The Create account button was disabled until the password met all complexity rules, confirmation matched and the name was nonempty. No field feedback explained why it could not be clicked, and the existing styling made the disabled state easy to miss. No staff command reservations were present after the user's reported attempt; this is consistent with the frontend gate, not proof of the exact text typed into their password fields.

The submit buttons are now disabled only while a request is running. Explicit client validation reports missing/invalid email, name, date, field lengths, password requirements and mismatched confirmation. Invalid fields have an accessible error description, a visible border, and focus moves to the first error. Validation never transmits invalid credentials, and server-side password/role/linkage checks remain unchanged. Profile editing and password reset use separate validation modes.

Verification: six new tests cover field diagnostics and the real component submit handler: invalid inputs remain clickable and show errors without an API call; valid inputs call the staff endpoint and clear the credential after success. The React-hook unit harness is local and does not claim browser/Auth end-to-end coverage. Complete suite: 153 passed, 0 failed, one live-support test skipped without a disposable session. Local no-network browser fixture showed field errors in Arabic and English. Staging build passed. No database/schema/Auth changes, no real staff accounts created, no production changes.
