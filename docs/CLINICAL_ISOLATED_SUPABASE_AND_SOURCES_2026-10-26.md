# تقرير Supabase المستقل وحزمة المراجع — 2026-10-26

الفرع: `feature/clinical-assistant-preview-v1`. لا دمج مع main، ولا تغيير لبيانات الصيدلية الحية أو أدوارها أو سياساتها أو متغيرات نشرها الإنتاجية.

## البيئة المستقلة

بعد تكرر خطأ إنشاء فرع Supabase، أظهر فحص الحساب منظمة واحدة باسم `nasrabdulhadi`. استُعلم عن تكلفة **مشروع جديد** فيها؛ أعاد Supabase `{amount:0, recurrence:monthly}`. أُنشئ المشروع `pharmacy-clinical-qa-isolated`، بالمرجع `vpjxdsprfcpqclnhbeoh`، منفصلاً عن المشروع الحي `eewjjzgwoaxhojnjvzgq`. تحقق الاستعلام من عدم وجود جداول public أو مستخدمي Auth قبل التهيئة. لم يُشترَ اشتراك أو تُؤكَّد تكلفة غير صفرية.

نسخة قاعدة الاختبار PostgreSQL 17.11؛ النسخة الحية المرصودة 17.6. هذا فرق بيئة يجب إبقاؤه ضمن حدود الاستنتاج.

أُنشئت أربعة منتجات **وهمية صريحة QA**: منتجان عامّان نشطان بعملتي USD/SYP، ومنتج مخفي، ومنتج مؤرشف. أُنشئ حسابا Auth وهميان بنطاق `example.invalid`، مدير ومستخدم عادي، دون إرسال بريد أو استخدام حسابات أشخاص. كلمتا المرور عشوائيتان ومحفوظتان خارج git؛ لا تستخدم أي مفاتيح service_role أو JWT secret. وُضع `role=admin` في user_metadata للحساب العادي عمداً لاختبار عدم الثقة به، بينما بقيت app_metadata.role=user.

## الاختبارات الحقيقية قبل الإصلاح وبعده

شُغّل SDK الفعلي على Auth وPostgREST الحقيقيين. نجح تسجيل الدخول للحسابين وتحقق `getUser()` من هويتهما. أُعيد كشف سعر الشراء على البيانات الوهمية قبل التعديل للزائر وللحساب العادي. هذه مرحـلة إثبات baseline، وليست ادعاء نجاح أمني.

طُبّق ملف `catalog-hardening.proposal.sql` **نفسه دون تعديل** على المشروع المستقل بعد تمرير شرط opt-in. نجح إنشاء دور القراءة المحدود والسياسات والدوال على Supabase المُدار بحساب postgres غير فائق الصلاحية. لم يُنفّذ الملف على المشروع الحي.

بعد الإصلاح نجحت **28 حالة API فعلية**، متضمنة تسجيلَي الدخول:

- رفض الطلب دون مفتاح، والتوكن الحقيقي بعد تعديل محتواه دون إعادة توقيعه.
- رفض قراءة سعر الشراء والفلترة به للزائر؛ الحساب العادي لا يرى صفوف الجدول الخاص.
- RPC الإدارة يعيد صفراً للزائر والحساب العادي، و`is_admin()` يبقى false رغم user_metadata.role=admin.
- الكتالوج العام يعيد المنتجين العامّين النشطين فقط وبالحقول الأحد عشر المسموح بها، مع بقاء سعر البيع والعملة صحيحين.
- رفض إسقاط/فلترة/ترتيب RPC العام باستخدام purchase_price، وعدم إتاحة schema الخاصة عبر Data API.
- نجاح محمّل الكتالوج العام المقوّى ومحمّل التدقيق الإداري عبر SDK وطلبات شبكة حقيقية وصفحات بحجم سجل واحد، دون ناقل وهمي.
- رفض INSERT غير المخوّل، ورفض UPDATE/DELETE أو إرجاع صفر صفوف، مع بقاء كل سجلات التجربة دون تغيير.
- بقاء وصول المدير إلى الأربعة منتجات والأسعار؛ تحديث سعر سجل وهمي ثم إعادته داخل finally، ومقارنة لقطة البيانات بعد كل الاختبارات.

بصمة سجلات المنتجات الأربع قبل الإصلاح وبعده وبعد اختبارات API: `b047ca9c1fc691ba3ab40a1bc281cbd9`، وعددها 4 في كل المقارنات. البصمة دليل اتساق هذه اللقطة، وليست توقيعاً أو تدقيقاً عاماً لكل كائن في القاعدة.

النتائج المنقحة محفوظة في `qa/clinical-security/results/`: baseline أربعة فحوص ناجحة، ثم hardened ثمانية وعشرون. لا تحتوي على كلمات مرور أو مفاتيح أو توكنات أو قيم من الصيدلية.

## ما لا يثبته الاختبار

هذا نموذج Supabase مستقل مصغّر: أنواع أعمدة المنتجات الثمانية عشر والسياسات المرصودة ودالتا is_admin وadmin_get_products_page، وليس نسخة كاملة من كل مخطط الصيدلية أو triggers أو القيود أو Storage أو Realtime أو دوال البيع والمحاسبة. اختبار حساب غير مدير هنا فعلي عبر Auth/API؛ **لم يجرِ تسجيل دخوله في واجهة التطبيق الحية بالمتصفح**.

نجاح هذه البيئة لا يغلق كشف السعر في القاعدة الحية. الاختبار أثبت أيضاً أن استعلام الكتالوج القديم يفشل بعد المقترح، بينما يعمل المحمّل الجديد. لذلك يلزم تنسيق backend مع تفعيل مسار الكتالوج الجديد في frontend ومراجعة الاعتمادات وخطة الرجوع قبل أي تطبيق حي؛ لا يجوز تطبيق SQL وحده على الأصل. لم يُغيّر `VITE_PUBLIC_CATALOG_ACCESS_V2` في Vercel.

فحص Advisor للمشروع المستقل أظهر تحذيرَي دوال SECURITY DEFINER قابلة للاستدعاء من anon/authenticated (is_admin وRPC الإدارة، مع تحقق صلاحية داخلي اختُبر)، وتعطيل حماية كلمات المرور المسرّبة. قابلية الاستدعاء وحدها ليست دليلاً على تسرب، ولا نعلن غياب كل المخاطر. إرشادات Supabase:

- https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable
- https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable
- https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

أُجري أيضاً فحص metadata قراءة فقط على الدوال الحية التي تذكر purchase_price ويمكن لـanon استدعاؤها: وُجدت إشارة is_admin في دوال الأعمال المرصودة؛ الاستثناءات دون الإشارة كانت من نوع trigger. هذا بحث نصّي محدود، **ليس برهاناً على سلامة تدفق التحكم أو اختباراً لكل RPC**. لم تُنفّذ دوال البيع أو الشراء أو التعديل الحية لاختبار رفضها.

## حزمة المراجع الأولية

جُمعت ثلاث حالات مراجعة من XML الرسمي لـDailyMed، مع معرّف النشرة والمستند والقسم والإصدار والتاريخ وSHA-256. تحقّق المُجمّع من وجود المقتطف حرفياً في قسم محدد، بحد 25 كلمة مقتبسة لكل نشرة، دون حفظ النشرة الكاملة أو استنتاج عدم وجود تداخل من غياب نص.

| أسماء الحالة في المصدر | إصدار SPL | تاريخ النشرة | القسم |
| --- | ---: | --- | --- |
| clopidogrel / omeprazole | 5 | 2025-05-30 | 7.2 |
| sildenafil / riociguat | 6 | 2023-11-17 | 4.3 |
| clarithromycin / simvastatin | 23 | 2023-05-30 | 5.4 |

هذه تواريخ نشرات بعينها، وليست تأكيداً أنها أحدث إرشادات كل دواء أو بلد. الروابط الأصلية ووقت الاسترجاع وبصمات المصدر في `CLINICAL_PRIMARY_LABEL_CASES_2026-10-26.json`.

أُضيف قسم مطوي في المساعد يعرض هذه المراجع وروابط نشراتها، مع تصدير CSV للمراجعة. الحزمة ليست نتيجة فحص الأدوية المختارة ولا تربط أسماءها تلقائياً بمنتجات الصيدلية. يرفض عارضها روابط غير رسمية ومعرّفات/تواريخ غير صالحة وادعاءات اعتماد داخل الملف وتعارضات السجل نفسه. التحقق في العارض بنيوي فقط؛ لا يعيد توثيق محتوى النشرة أو هوية مراجع أو حقوق الاستخدام.

كل الحالات `pending` و`clinical_approved=false` و`license_status=unknown`. **لم يُفعّل أي حكم سريري أو توصية علاج أو قاعدة تداخلات معتمدة**. CSV يترك بيانات المراجع والتاريخ والملاحظات فارغة ولا يمنح موافقة. أداة Python أصبحت تتحقق/تحدّث المقتطفات المنتقاة من manifest؛ إذا تغير النص تتوقف ولا تستبدله بتوصية مستنتجة.

- 3 اختبارات حماية جديدة تثبت أن مشغّل الاختبار البعيد يرفض المشروع الحي أو أصله أو مفتاح secret قبل بدء تسجيل الدخول أو الاختبارات.

## المتبقي

1. إغلاق كشف السعر في البيئة الحية يحتاج مراجعة مخططها الكامل وتغيير صلاحية القراءة ونشر frontend متوافق؛ يظل ذلك خارج قيد عدم تغيير الصلاحيات الحية وعدم الدمج مع الأصل.
2. مراجعة بيانات المنتجات والمطابقات والتراكيب ما زالت مستقلة عن هذه الاختبارات؛ لم تُملأ 5,061 حالة نقص تلقائياً من أسماء تجارية أو تخمينات.
3. الترخيص والتحقق الصيدلاني المستقل والتقييم المرجعي للتداخلات والتنبيهات المتقدمة والحمل والإرضاع والكلى والعمر والجرعة والطريق ما زالت بوابات قبول غير منجزة.
4. اختبار العرض المتجاوب السابق قائم، لكن هاتفاً فعلياً وتنزيلات الهاتف وبعض سيناريوهات الشبكة لم تُعتمد بعد.

الأصل وبياناته وصلاحياته لم تتغير. لا يُعلن اكتمال الإضافة أو خلوها من الأخطاء أو صلاحيتها لاتخاذ قرار سريري.
